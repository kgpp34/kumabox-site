Open-source microVM sandbox runtime开源 microVM 沙箱运行时

A disposable computer for every agent task.每个 Agent 任务，
一台用完即弃的电脑。

KumaBox gives every agent its own KVM microVM: its own kernel, disk and network namespace. It is built to pack many sandboxes onto one host, takes OCI images and CNI networks as they are, and forks a warmed-up machine in tens of milliseconds.KumaBox 给每个 Agent 一台独立的 KVM 虚拟机：独立内核、独立磁盘、独立网络命名空间。它为单机高密度部署而设计；直接使用现有的 OCI 镜像和 CNI 网络；预热好的机器几十毫秒就能分叉出一台新的。

Why not just Docker为什么不直接用 Docker

Agents run code nobody reviewed. Containers were not built for that.Agent 执行的是没人审过的代码，容器不是为此设计的。

Many teams start with Docker as a sandbox. It works for a demo, then hits three walls as soon as agents do real work at scale.很多团队一开始用 Docker 当沙箱。演示时没问题，Agent 一旦开始规模化地干真活，就会撞上三堵墙。

Isolation隔离

One kernel, shared by everyone所有任务共用一个内核

A single kernel bug is a path out of every container on the host. KumaBox puts each task behind KVM with its own guest kernel.一个内核漏洞，就可能让宿主机上所有容器失守。KumaBox 让每个任务都有自己的 guest 内核，运行在 KVM 硬件边界之内。

snapshot / restore

No memory snapshots没有内存级快照

Docker checkpoints still depend on experimental CRIU support. Without them you cannot warm an environment once and fork it, or park an agent and resume it later. KumaBox makes both routine.Docker 的 checkpoint 至今依赖实验性的 CRIU。做不到预热一次再分叉，也做不到把 Agent 挂起、之后原样恢复。KumaBox 把这两件事变成日常操作。

Full OS完整系统

Desktops and browsers need privileges桌面和浏览器需要特权

Computer-use and browser agents want systemd, a desktop and a real browser. In a container that usually means --privileged, which weakens isolation further. A microVM is simply a full Linux machine.Computer Use 和浏览器 Agent 需要 systemd、桌面和完整浏览器，放进容器往往要开 --privileged，隔离反而更弱。microVM 本身就是一台完整的 Linux 机器。

Design goals设计目标

Light enough to run everywhere, dense enough to run everything.轻到随处可装，密到装得下所有 Agent。

Lightweight轻量

1 binary

Install it on any Linux host with KVM. Nothing else to operate.任何带 KVM 的 Linux 主机都能装，没有其他组件要运维。

  • No resident daemon.零守护进程。 Each command opens state, takes locks, acts and exits. Only the VMs keep running.每条命令打开状态、加锁、执行、退出，只有虚拟机在运行。
  • No external services.零外部依赖。 Metadata lives in embedded SQLite. No database, cache, object store or Kubernetes.元数据存在嵌入式 SQLite，不需要数据库、缓存、对象存储或 K8s。
  • One VMM process per sandbox.每沙箱一个 VMM 进程。 Cloud Hypervisor with direct kernel boot; one sandbox failing never takes others down.Cloud Hypervisor 内核直启动，一个沙箱出问题不会拖垮其他沙箱。
  • Host check built in.内置主机体检。 kumabox doctor --fix verifies KVM, the VMM, CNI and EROFS tools.kumabox doctor --fix 检查并修复 KVM、VMM、CNI 和 EROFS 工具链。

High density高密度

shared pages

Each extra sandbox pays only for what it changes.多一个沙箱，只为它改动的部分付费。

  • Image layers shared host-wide.镜像层全机共享。 OCI layers become read-only EROFS disks served from the host page cache, so a base system sits in memory once.OCI 层转成只读 EROFS 盘，走宿主页缓存，同一套基础系统在内存里只存一份。
  • Clones share memory pages.克隆共享内存页。 Snapshot memory is hard-linked and restored copy-on-write; untouched pages stay shared across clones.快照内存硬链接共享，以写时复制方式恢复，未修改的页在克隆之间共享。
  • Idle memory goes back.空闲内存归还。 virtio-balloon with free page reporting returns memory the guest frees.virtio-balloon 开启 free page reporting，guest 释放的内存交还宿主。
  • Disks on demand.磁盘按需占用。 Sparse copy-on-write disks, reflinked on clone, with direct I/O so data is not cached twice.稀疏写时复制盘，克隆时 reflink 共享，direct I/O 避免重复缓存。

Secure by default默认安全

KVM boundary

Every input is treated as untrusted, including the guest.所有输入都按不可信处理，包括 guest 本身。

  • Own kernel, own process, own cgroup.独立内核、进程与 cgroup。 The VMM is born inside its cgroup via CLONE_INTO_CGROUP, so there is no window before it is confined.VMM 通过 CLONE_INTO_CGROUP 在创建瞬间就落入专属 cgroup，没有先启动再移入的空档。
  • Safe clones.克隆安全。 NICs are swapped while the clone is still paused, and the guest kernel's CRNG is reseeded, so clones never share an address or random state.在克隆仍暂停时换网卡，并强制 guest 内核 CRNG 重新播种，副本之间不会共用地址或随机数状态。
  • No SSH.不需要 SSH。 Commands travel over vsock with bounded frames; no port is exposed to run them.命令走 vsock，消息帧有上限，执行命令不暴露任何端口。
  • Hostile images handled.镜像按不可信处理。 Decompression limits, no link following, digest pinning and credential-safe registry errors.解压限额、不跟随链接、digest 锁定，Registry 报错不泄露凭据。

Container-native原生兼容容器生态

OCI · CNI

Keep your Dockerfiles, CI pipeline, registry and network plugins.Dockerfile、CI 流水线、镜像仓库和网络插件都沿用。

  • OCI images are first-class.OCI 镜像是一等公民。 Pull from any registry, a local Docker daemon, an OCI layout or a tar archive.可从任意 Registry、本地 Docker、OCI 目录或 tar 归档导入。
  • Reproducible conversion.可复现的转换。 The same image converts to byte-identical EROFS on every host.同一镜像在任何主机上都转换出逐字节一致的 EROFS。
  • Standard CNI.标准 CNI。 Reads /etc/cni/net.d and /opt/cni/bin, the same plugins your containers use.读取 /etc/cni/net.d 与 /opt/cni/bin，和容器用的是同一套插件。
  • Real devices when you need them.需要时接入真实设备。 Hot-plug data disks, virtio-fs shares and VFIO PCI devices such as GPUs.热插拔数据盘、virtio-fs 共享目录，以及 GPU 等 VFIO PCI 设备。

Running snapshots运行态快照

Warm once, fork many.预热一次，分叉 N 份。

Agents retry, branch and explore. Pay for boot, installs and warm caches one time, then give every attempt its own copy of a ready machine.Agent 天生会重试、分支、并行探索。开机、装依赖、热缓存只付一次成本，之后每次尝试都拿到一台准备好的机器副本。

Running snapshot运行态快照

Memory, devices and disk at one pause point; the source resumes at once.同一暂停点捕获内存、设备与磁盘，源沙箱随即恢复。

clone × N

N fresh sandboxesN 台新沙箱

Same warm state; new ID, IP, hostname, entropy and VMM.继承预热状态，换新 ID、IP、主机名、熵与 VMM。

Paid once:只付一次： boot and setup, often minutes开机加装环境，常常是分钟级
Per attempt:每次尝试： one clone一次克隆

restore

Roll a sandbox back to the snapshot in place, for agents that try, fail and try again.原地回滚到快照点，适合反复试错的 Agent。

hibernate

Persist the full state and release the VMM. A parked agent costs no CPU or memory.持久化完整状态后释放 VMM，挂起的 Agent 不占 CPU 和内存。

export / import

Sparse, checksummed archives that carry their image digest. Move a warmed environment to another host and clone it there.稀疏、带校验、锁定镜像 digest 的归档。把配好的环境搬到另一台主机直接克隆。

Quick start快速开始

From an OCI image to a forked sandbox in six commands.六条命令，从 OCI 镜像到分叉出的沙箱。

You need an amd64 or arm64 Linux host with /dev/kvm and root. Preview builds and the matching guest image are on the Releases page.需要一台能访问 /dev/kvm 的 amd64 或 arm64 Linux 主机，并具备 root 权限。预发布包和配套 guest 镜像见 Releases。

# 1. build and install
git clone https://github.com/kgpp34/KumaBox.git && cd KumaBox && make build
sudo install -m 0755 bin/kumabox bin/kumabox-check /usr/local/bin/

# 2. prepare the host once: Cloud Hypervisor, firmware, CNI, EROFS tools
sudo kumabox-check --upgrade && sudo kumabox doctor

# 3. pull the guest image
sudo kumabox image pull ghcr.io/kgpp34/kumabox/ubuntu:24.04

# 4. run a sandbox and talk to it
sudo kumabox run ghcr.io/kgpp34/kumabox/ubuntu:24.04 --name my-vm --cpus 2 --memory 1GiB
sudo kumabox exec my-vm -- uname -a

# 5. warm once, fork many
sudo kumabox snapshot save my-vm --name base
sudo kumabox clone base --name fresh --wait-network

# 6. clean up
sudo kumabox stop fresh my-vm && sudo kumabox rm fresh my-vm
sudo kumabox snapshot rm base
